# Отчёт о проверке защиты production-настроек (Negative Testing)

**Дата проверки:** 25.11.2026  
**Окружение:** Production (`ENV=production`)  
**Статус:** Пройдено успешно (Passed)

Проверка устойчивости конфигурации приложения в production-окружении к небезопасным параметрам, значениям по умолчанию и попыткам обхода ограничений при редактировании.

## 1. Негативные сценарии при инициализации (Startup Validation)

| Категория | Негативный сценарий (Input) | Ожидаемый результат | Фактический результат | Статус |
| :--- | :--- | :--- | :--- | :--- |
| **DEBUG-режим** | Установлено `DEBUG=True` (или `"1"`, `"true"`) при `ENV=production` | Отказ запуска; логирование критической ошибки конфигурации | Приложение завершило работу при старте с ошибкой `ImproperlyConfigured: DEBUG cannot be True in production` | [x] |
| **Demo-режим** | Установлено `DEMO_MODE=True` в production-окружении | Отказ запуска либо принудительное отключение демо-авторизации и тестовых данных | Запуск заблокирован на этапе валидации окружения (`DEMO_MODE` запрещён в production) | [x] |
| **Пустой `SECRET_KEY`** | Передана пустая строка `""`, пробелы `"   "` или `None` | Ошибка валидации при старте; запуск заблокирован | Выброшено исключение `ImproperlyConfigured: SECRET_KEY must not be empty` | [x] |
| **Слабый `SECRET_KEY`** | Передан ключ короче 32–50 символов или с низкой энтропией (например, `"a" * 64`) | Ошибка валидации при старте; запуск заблокирован | Выброшена ошибка валидации: недостаточная длина / низкая энтропия ключа | [x] |
| **Дефолтный `SECRET_KEY`** | Передано значение из шаблона (`django-insecure-...`, `changeme`, `secret`) | Ошибка валидации при старте; запуск заблокирован | Обнаружен небезопасный префикс/шаблон ключа; запуск приложения прерван | [x] |
| **Небезопасные Cookies** | `SESSION_COOKIE_SECURE=False` или `CSRF_COOKIE_SECURE=False` | Ошибка запуска либо принудительная перезапись в `True` | Валидатор отклонил запуск с ошибкой конфигурации безопасности кук | [x] |
| **Доступ к Cookies из JS** | `SESSION_COOKIE_HTTPONLY=False` | Ошибка запуска либо принудительная перезапись в `True` | Запуск заблокирован; флаг `HttpOnly` защищён от отключения в production | [x] |
| **Политика SameSite** | `SESSION_COOKIE_SAMESITE='None'` при `SESSION_COOKIE_SECURE=False` | Отказ запуска из-за несовместимости атрибутов безопасности | Ошибка валидации конфигурации: `SameSite=None` требует `Secure=True` | [x] |
| **Отсутствие `.env`** | Запуск без файла `.env` и без системных переменных окружения (проверка fallback-значений в коде) | Приложение не использует захардкоженные пароли/ключи по умолчанию и требует явной передачи секретов | Запуск прерван с ошибкой отсутствия обязательных переменных окружения | [x] |

## 2. Проверка редактирования настроек и попыток обхода (API / Admin)

| Сценарий | Действие (Input) | Ожидаемый результат | Фактический результат | Статус |
| :--- | :--- | :--- | :--- | :--- |
| **Допустимое редактирование** | Обновление разрешенных бизнес-настроек (название площадки, лимиты пагинации) | Изменения сохранены (`200 OK`); флаги безопасности (`DEBUG`, `SECRET_KEY`) не затронуты | Получен статус `200 OK`, бизнес-настройки обновлены, системные параметры остались без изменений | [x] |
| **Частичное обновление (`PATCH`)** | Отправка одного запрещенного поля: `{"DEBUG": true}` или `{"session_cookie_secure": false}` | Запрос отклонен (`400 Bad Request` / `403 Forbidden`) или поле проигнорировано (`read_only`) | Сервер проигнорировал системные поля (`read_only`) и вернул ошибку валидации `400 Bad Request` | [x] |
| **Подмена типов данных** | Передача строковых/числовых эквивалентов вместо булевых: `{"DEBUG": "1"}`, `{"DEMO_MODE": 1}` | Небезопасный режим не активируется; ошибка валидации или игнорирование | Небезопасный режим не активирован, поля отклонены сериализатором (`400 Bad Request`) | [x] |
| **Сброс в `null`** | Передача `{"SECRET_KEY": null}` | Система не откатывается к значению по умолчанию из кода; ошибка `400 Bad Request` | Запрос отклонён (`400 Bad Request`), отката к дефолтному значению не произошло | [x] |
| **Включение Demo-режима** | Попытка активировать `DEMO_MODE` через API после запуска в production | Блокировка изменения (`400` / `403`) | Попытка заблокирована, получен статус `403 Forbidden` | [x] |
| **Контроль доступа (Гость)** | Запрос к эндпоинтам настроек без авторизации | Отказ в доступе (`401 Unauthorized`) | Получен статус `401 Unauthorized` | [x] |
| **Контроль доступа (Продавец/Юзер)** | Попытка чтения или изменения системных настроек обычным пользователем | Отказ в доступе (`403 Forbidden`) | Получен статус `403 Forbidden` | [x] |

## 3. Автоматизированная проверка перед деплоем (CI/CD)

* **Команда проверки:**
  ```bash
  python manage.py check --deploy --fail-level WARNING
  ```
* **Ожидаемый результат:** команда завершается с кодом `0`, предупреждения уровня `security.W*` (связанные с `DEBUG`, `SECRET_KEY`, `SSL` и `Cookies`) отсутствуют.
* **Фактический результат:** 
  ```text
  System check identified no issues (0 silenced).
  Exit code: 0
  ```
