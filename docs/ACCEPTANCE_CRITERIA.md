# Критерии готовности IRSbese

## Каталог
- Пользователь видит только активные товары.
- Поиск работает по названию, описанию и категории.
- Фильтр категории и сортировка не вызывают ошибку.
- Неизвестный ID товара приводит к 404.
- Пустая выдача имеет понятное состояние.

## Аккаунт и доступ
- Регистрация проверяет обязательные поля и уникальность email или телефона; достаточно одного контактного идентификатора.
- Пароль хранится как хэш.
- Вход и выход работают.
- POST-формы защищены CSRF.
- Покупатель не получает доступ к функциям продавца.
- Пользователь видит только собственные заказы.

## Корзина и заказ
- Количество товара — целое число от 1 до доступного остатка.
- Сумма вычисляется на сервере по цене из БД.
- Пустая корзина не оформляется.
- Остатки проверяются повторно непосредственно перед сохранением заказа.
- Заказ и позиции сохраняются одной транзакцией.

## Продавец
- Продавец может добавить товар с названием, категорией, описанием, ценой, остатком и изображением.
- Изображения проходят проверку типа и ограничения размера.
- Продавец не может управлять товарами другого продавца.
- Публикация товаров 18+ запрещена в текущем MVP.

## Оплата
- До согласования оплаты `PAYMENTS_ENABLED=0`.
- Платёж создаётся только на сервере на сумму из заказа.
- Данные банковской карты не собираются сайтом.
- Статус «Оплачен» устанавливается только после подтверждения через API провайдера.
- Webhook сверяет ID, сумму, валюту и metadata; повторное событие обрабатывается безопасно.

## Качество и релиз
- Все P0/P1 тест-кейсы пройдены и приложены логи.
- Проверка ширин 390, 768 и 1280 px должна быть подтверждена скриншотами реального приложения.
- Пройдена проверка чистого запуска по README.
- Нет секретов в репозитории.
- Есть резервная копия и подтверждённый план восстановления.
- Релиз не считается завершённым без фактического production smoke-теста.
