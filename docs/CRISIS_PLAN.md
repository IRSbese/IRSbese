# Антикризисный план IRSbese

## 1. Сбой сайта
- Зафиксировать время, URL и сообщение об ошибке.
- Проверить `systemctl status irsbese`, журналы systemd и Nginx.
- Если сбой связан с последним релизом — остановить дальнейшее обновление и выполнить откат.
- Не удалять БД и uploads при диагностике.
- После восстановления выполнить smoke-тест.

## 2. Потеря или повреждение базы
- Остановить запись в приложение.
- Сохранить повреждённый файл для расследования.
- Восстановить последнюю проверенную резервную копию в отдельный путь.
- Проверить целостность SQLite и выборочно проверить заказы.
- Переключить приложение на восстановленную БД только после проверки.

## 3. Утечка ключей
- Немедленно отключить соответствующий ключ у провайдера.
- Выпустить новый ключ и заменить переменную окружения.
- Проверить логи и историю доступа.
- Удалить секрет из истории репозитория и выполнить ротацию всех затронутых секретов.
- Уведомить ответственных.

## 4. Ошибка платежей
- Отключить `PAYMENTS_ENABLED`.
- Не менять заказ на «Оплачен» вручную без подтверждения провайдера.
- Сверить ID платежа, сумму, валюту и metadata в кабинете ЮKassa.
- Возобновлять платежный поток только после тестирования исправления.

## 5. Критическая уязвимость
- Ограничить доступ к затронутому функционалу.
- Сохранить логи, не публикуя персональные данные.
- Исправить проблему, добавить регрессионный тест.
- Возобновить работу после проверки QA и PM.

## Контакты
Вписать реальные контакты владельца VPS, PM, разработчика и провайдера до production-релиза. Не подставлять вымышленные контакты.
