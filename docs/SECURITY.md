# Модель безопасности и ограничения

- Пароли хэшируются Werkzeug; исходные пароли не сохраняются.
- Все изменяющие формы используют CSRF-токен.
- Проверка ролей и владельца выполняется на сервере.
- SQL-запросы используют параметры, динамическая сортировка выбирается из белого списка.
- Изображения проверяются Pillow и сохраняются в WebP; лимит запроса 5 МБ.
- Платёжная интеграция не хранит данные банковских карт. Карточные данные вводятся только на стороне ЮKassa.
- Webhook перепроверяет платёж через API, сверяет сумму, валюту и order_id; повторные уведомления обрабатываются идемпотентно.
- В production использовать HTTPS, `COOKIE_SECURE=1`, уникальный SECRET_KEY, закрытый `.env`, ограниченные права пользователя сервиса и регулярные бэкапы.
- Восстановление пароля требует SMTP; токен хранится в виде SHA-256-хэша и имеет срок 30 минут.
- Для коммерческого запуска нужны политика конфиденциальности, согласия, сроки хранения и юридическая проверка требований к персональным данным.
