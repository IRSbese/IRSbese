# IRSbese — уточнённые требования MVP

## Назначение
IRSbese — учебный маркетплейс для поиска и размещения товаров. Цель MVP — показать полный путь покупателя и базовую работу продавца.

## Пользователи и роли
- Покупатель: регистрация и вход по электронной почте или телефону, каталог, поиск, карточка товара, корзина, заказ, история заказов, профиль.
- Продавец: регистрация с названием компании и ИНН, вход, создание товара, редактирование, скрытие и повторная публикация своих товаров.
- Администратор/модератор: роль и отдельная панель администратора в текущем MVP не реализованы. Проверка продавца и товаров перед публичным коммерческим запуском должна быть назначена ответственному лицу.

## Принятые ограничения MVP
- Аудитория: 12+ для обычных товаров. Товары категории 18+ запрещены к размещению в этой версии.
- Онлайн-оплата: интеграция ЮKassa подготовлена для тестового режима. Она включается только при наличии тестового Shop ID и Secret Key из переменных окружения. По умолчанию отключена. Реальные платежи не включать.
- Доставка: покупатель выбирает «Курьер» или «Самовывоз». Интеграции со службами доставки и расчёта тарифа нет.
- Продавец указывает компанию и ИНН. Автоматической проверки ИНН и юридического статуса компании нет.
- Фотографии: JPG, PNG, WEBP; ограничение запроса — 5 МБ; изображения преобразуются в WebP.
- Валюта — RUB.

## Функциональные требования
1. Каталог показывает только активные, одобренные и не относящиеся к категории 18+ товары.
2. Поиск выполняется по названию, описанию и категории; доступны фильтр категории и сортировка.
3. Корзина позволяет добавить товар, изменить количество, удалить позицию и пересчитать сумму на сервере.
4. Количество должно быть целым числом от 1 до 99 и не превышать складской остаток.
5. При создании заказа сервер повторно получает цены и остатки из БД и сохраняет заказ с позициями транзакционно.
6. Покупатель видит только собственные заказы.
7. Продавец видит и меняет только собственные товары.
8. Пароли хранятся только в виде стойкого хэша; формы защищены CSRF.
9. Восстановление пароля использует одноразовый токен с ограниченным сроком действия. Отправка письма требует настройки SMTP.
10. Рекомендации используют покупки, просмотры, похожую категорию, популярность и сопутствующие покупки.
11. Платёж считается успешным только после проверки состояния через API ЮKassa и сверки суммы, валюты и номера заказа.
12. Повторное уведомление ЮKassa не должно создавать повторный заказ или повторное списание остатков.

## Нефункциональные требования
- Flask, SQLite для учебного MVP, Gunicorn для запуска.
- Секреты только в окружении; `.env` не коммитить.
- HTTPS обязателен в production; после настройки HTTPS включить `COOKIE_SECURE=1`.
- Защита от CSRF, безопасные заголовки, ограничения загрузки файлов, проверка прав на сервере.
- Резервное копирование БД и загруженных изображений.
- Перед промышленной эксплуатацией заменить SQLite на управляемую БД и провести нагрузочное/безопасностное тестирование.
